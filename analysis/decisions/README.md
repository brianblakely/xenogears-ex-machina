# Intentional-change records

No game behavior is implemented in Phase 0. The requested modern rendering and
convenience defaults are requirement specifications, not observed fixes.

Before implementing an intentional difference, create a record containing an ID,
requirement facets, independently observed original behavior/findings, desired
behavior, rationale, affected content IDs and state domains, default/option
interaction, migration/compatibility effects, tests and review. If original
behavior is unknown, label that fact and do not claim a correctness fix.

Unknown behavior stays in the subsystem/content backlog. Do not relabel a missing
implementation, silent fallback, or progression workaround as an intentional
change. First-person missing-surface repairs and wide-framing content repairs need
original asset provenance and remain separate from renderer changes.
