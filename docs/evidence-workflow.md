# Evidence boundaries

Implementation starts with [matching](matching.md), not a new evidence ceremony.
Use the user's unmodified, hash-qualified original inputs. Other Xenogears
implementations or undocumented claims from an AI are not implementation sources;
general-purpose tools are permitted. Keep original payloads local.

## Choose evidence for the actual claim

For original-target code, keep the qualified source identity, reproducible target
configuration and exact linked-image comparison. Matching code/data/layout is the
primary Phase 1 check; it does not identify historical source text, explain every
semantic name, measure source coverage or prove native portability. Original
assembly placeholders can produce an exact image without completing decompilation.

For an unresolved format, semantic, timing or integration question, reuse existing
source and captures first. Collect a new original observation only when needed.
Record profile, executable/overlay identity, coordinates, tool configuration,
inputs, expected and actual effects, artifact identities and remaining uncertainty.
A shared capture can answer several questions; a small matched helper does not
need its own new capture, findings file and set of duplicated status updates.

Expected results come from independent original evidence, never from the new
implementation. Do not edit pristine inputs, normalize away final mismatches,
invent expected outcomes or treat matching prefixes as complete lifecycle passes.
Public synthetic fixtures validate tooling and boundary behavior, not original-game
fidelity. Native adaptations need behavioral and integration regression tests.

## Preserve knowledge without duplicating status

Record genuinely new knowledge in a concise source comment, format note or finding.
The existing finding template and validators remain available for structured
observations; they are not extra per-function requirements for exact matches.
Distinguish observed facts, interpretation, untested paths and intentional changes.
Retain historical findings at their measured scope, including failures and limits.

Historical `tests/validation-results.json`, Phase 0 verification and old facet
labels are evidence records, not the current checklist. Do not regenerate a
requirements matrix to update them. `plan.md` owns phase scope; actual source,
build inputs and executable tests own current implementation status.

Publish independently authored source/explanations and factual metadata. Original
images, extracted code/data, generated disassembly, captures and personal saves
remain private. A container integrity check is not evidence of game correctness,
and source identity alone does not establish a supported native runtime.
