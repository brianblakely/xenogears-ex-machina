# Phase 1 slice analysis contract — reviewed scope

Phase 1 prepares independently recovered source for Phase 2 and the playable
slice in Phase 3. It does not claim a shipping runtime, native platform execution,
or complete analysis of both discs. The plan explicitly continues analysis after
this exit. The broad Phase 1 facets and unchecked todos remain visible.

## Selected original scenario

The primary candidate is Disc 1 numeric field 23, bound to source profile
na-slus-00664-39c547a9afc6, physical source slot 652, logical LBA 124528.
The source and original execution show a forest with Fei, an entry dialogue,
controllable movement and collision. Its 25-actor event package has four
interaction entries (actors 14–17) that call original opcode 0x71 with formation
row 0 and continue through explicit post-battle instructions. The loader obtains
that formation table from field 23's own component 6. This is a concrete
field/event/battle candidate, rather than a room display or the all-zero Kernel
battle default.

The selected encounter must be reached through an ordinary input route or an
independently recovered and reviewed setup contract. A schedule completing is not
evidence that an encounter occurred. The entry prerequisites, actual triggering
actor, encounter participants, outcome, rewards and returned event state remain
open until original execution demonstrates them.

Adjacent numeric fields, including candidate field 25's observed camp dialogue,
may be included only after their ordinary transition and progression conditions
are established. No semantic location name is assumed. A final source-qualified
manifest must freeze the actual route before the exit can pass.

## Required proof at the exit

Each requirement below needs specific original-source coordinates, readable
reconstruction, local original-data comparisons, public synthetic malformed-input
tests where relevant, independent review, and explicit remaining limitations.
Unobserved expected outcomes remain unknown.

| Required domain | Evidence needed for this slice |
| --- | --- |
| Source and loading | Exact supported profiles, disc/FAT/directory/sector arithmetic, executable and overlay identities, compression with logical versus physical bounds, every resource used by the route and its initialization/return lifetime |
| Field representation | Field header/components; the geometry, material, texture/palette, sprite/animation, camera and collision structures actually used by the route; source-to-runtime correlations and bounded parsing |
| Script execution | Every reachable instruction and branch used by the frozen route, typed operands, variable signedness, actor/slot scheduling, waits, dialogue and its controls, triggers, transitions, battle request and resumed side effects; an independently authored disassembler with precise errors for unknown instructions |
| Field behavior | Walking, running, jumping, collision, camera rotation, interaction and ordinary map transitions on the route; normal and boundary original observations, exact recovered state/arithmetic, and the event conditions governing player control |
| Encounter and return | Actual on-foot encounter entry, participants and formation, command/target selection, representative attacks and damage, enemy turn rules, victory/failure conditions, rewards, and ordinary field/event return; controlled RNG/state observations and the used formula branches |
| Menu and persistence | The slice's main menu, inventory/equipment actions and ordinary valid save/load context; recovered state layout/checksums, round trip and failure handling against original execution |
| Required media | The music/sample/effect paths used by the slice and a source-qualified FMV-to-gameplay transition required by Phase 3; game-specific framing/sequence/trigger semantics and observable timing, with general-purpose codec boundaries documented |
| Time and services | Original controller/disc/BIOS/GPU/audio/interrupt-facing intent and native service contracts; observed simulation cadences, waits, asynchronous ordering and arithmetic; HLE/core observations distinguished from hardware timing proof |
| Reproducibility and remainder | Immutable original runs and source checks, reviewed source-only tests, independent replay/state comparisons, and explicit unresolved symbol/format/opcode/content inventories with owners/next experiments |

The expanded plan also requires source-qualified visual and Mono/Stereo/Wide
signal references for the frozen slice, and recovered state ownership, semantic
actions, spawn/setup validity and distinct readiness predicates for native agent
queries. These obligations are now explicitly mapped into the unresolved field
representation, required-media and field-behavior proofs. No tick rate, decoder,
typed setup or original behavior is inferred from the Phase 0 protocol design.
The [native first-slice gates](agent/acceptance.json) additionally govern the later
Phase 2/3 implementation and do not receive a pass from this analysis manifest.

This gate cannot pass if a required path uses a guessed formula, synthetic
behavioral oracle, silent unknown opcode, debugger-only progression bypass,
unexplained state mask, or an unreviewed resource interpretation. Readiness and
timing scope must be explicit.
